# Local OAuth / OpenID Connect provider

API: `startOAuthProvider({ clients: [{ clientId, clientSecret, redirectUris }], accounts?, issuer?, endpoints?, faults?, now?, codeTtlMs?, tokenTtlMs?, interactionTtlMs?, listen? })` from `@openwork/labs/oauth` (also root export). Returns `{ baseUrl, issuer, endpoints, publicEndpoints, events, registerClient, setFaults, stop, [Symbol.asyncDispose] }`. It is valid to start with `clients: []` then call `registerClient({ clientId, clientSecret, redirectUris: [exactDenCallback] })` after Den binds its port. Registering an existing client ID replaces its secret and redirect allowlist; inputs are copied (not retained by reference).

Defaults emulate Google: issuer `https://accounts.google.com`; public authorization `https://accounts.google.com/o/oauth2/v2/auth`, token `https://oauth2.googleapis.com/token`, JWKS `https://www.googleapis.com/oauth2/v3/certs`, userinfo `https://www.googleapis.com/oauth2/v3/userinfo`, discovery `https://accounts.google.com/.well-known/openid-configuration`. `endpoints` gives the same paths on `baseUrl`; `publicEndpoints` gives those real-shaped URLs. Discovery advertises public endpoints, not loopback. Override issuer/endpoints for other providers.

An integration preload can rewrite each public endpoint to `endpoints`, preserving method, headers, query and body. Browser routing must also proxy `/mock-oauth/select` and `/mock-oauth/consent` on the authorization origin to the same paths on `baseUrl`. No TLS interception, real Google calls, secrets or external dependencies are required by this fixture. The HTTP fixture itself accepts paths independent of Host; restrict interception to exact configured origins/paths in the integration layer.

Flow: GET authorization → **Choose an account** with POST form (account buttons contain name + email and avatar initial; field `account`) → POST `/mock-oauth/select` (`interaction`, `account`=account sub) → 303 consent URL → GET **Sign in to OpenWork** consent page → **Continue** (`decision=approve`) / **Cancel** (`decision=deny`) → POST consent (`interaction`, `decision`) → 302 registered callback, preserving state verbatim. Optional client `displayName` replaces OpenWork in headings. Pages use an offline, Google-shaped two-column rounded white card, inline Google logo, readable permission descriptions, responsive layout, keyboard focus rings and an explicit **Local OAuth test provider** footer. They load no fonts, images, scripts or other external resources. Inline CSS is permitted by the page CSP; scripts remain blocked. `login_hint` can label a matching account but never creates an arbitrary identity. Accounts default to a fictional `oauth.user@acme.test` identity; pass explicit accounts for scenarios. Transactions are server-held and expire. Redirect URIs must be explicitly registered exactly; invalid requests never redirect. PKCE is optional, but challenges must be S256 and verifiers are enforced. Confidential clients authenticate by client_secret_post or client_secret_basic. Codes are single use, including failed redemption after successful client authentication.

`events` is an ordered in-memory witness array; entries have `type`, `at` and relevant safe `clientId`, `redirectUri`, `sub`, `scope`, `state`, `error` fields. No code, access token, ID token, secret, verifier or interaction identifier is recorded. Events distinguish authorize, account selection, consent, code issuance, token exchange, userinfo, discovery, JWKS and rejection. The `setFaults({...})` method replaces faults for subsequent requests; faults: `denyConsent`, `expiredCode`, `invalidClient`, `invalidGrant`, `nonceMismatch`, `badSignature`. Code-related faults are captured when issued; token-related faults apply when exchanged. `now` is an injectable millisecond clock for deterministic expiration tests. Default code/interaction/access-token lifetimes are 60 seconds / 5 minutes / 5 minutes.

This is deliberately separate from `idp.ts`'s enterprise SSO/SAML knobs: that fixture allows unregistered redirects and lacks PKCE/code expiry checks, so changing it would alter existing enterprise scenarios. This provider reuses its dependency-free RS256 JWT signing primitive.

Run protocol tests with working directory `evals`: `pnpm exec vitest run --project pr packages/labs/src/oauth/provider.test.ts`.
