Choose your operating system and follow its steps to save a local conversation-history
backup. This guide covers standard local desktop installations, not OpenWork Cloud,
a remote engine, or your organization's server database.

<Tabs>
  <Tab title="Windows">

    <Steps>
    <Step title="Quit OpenWork">

    Finish running tasks and fully quit OpenWork. Close other OpenWork or OpenCode
    instances using the same data. If an app doesn't close normally, ask your
    administrator or OpenWork support for help before copying.

    </Step>
    <Step title="Locate the source folders">

    Use the **File Explorer address bar** to open each parent folder. Enter its path
    and press **Enter**. Confirm that the named folder exists in that parent.

    | Open this parent folder | Select this folder |
    | --- | --- |
    | `%APPDATA%` | `com.differentai.openwork` |
    | `%APPDATA%` | `openwork` |
    | `%USERPROFILE%\.local\share` | `opencode` |

    These are navigation paths, not PowerShell commands. If any location is custom,
    missing, or uncertain, stop before copying. Ask your administrator or OpenWork
    support to [confirm the actual paths](#custom-storage-and-other-installations).
    Share only paths. Don't share configuration files or credentials.

    </Step>
    <Step title="Prepare the destination">

    Create a dated backup folder outside the source folders. The copies can contain
    private conversations and credentials, so use an encrypted or IT-approved
    protected location. Don't upload them to a public issue, support chat, or Slack.

    Record the app version and each source folder's full original path. If sources
    share a name, use distinct destination folders. Keep each copy paired with its
    source path, and don't merge copies from different sources.

    </Step>
    <Step title="Copy the folders">

    From each parent folder, select the **named source folder itself** and use
    **Copy**, not **Cut**. Open its backup destination and use **Paste**. Repeat for
    every required source folder. Include hidden files and database sidecars in each
    folder copy. Don't copy only `.db` files. Leave the originals unchanged.

    </Step>
    <Step title="Check completion">

    Wait for every required folder to finish copying without errors and confirm
    that you recorded each original path. Resolve missing folders or copy errors
    before treating the file capture as complete. Then reopen OpenWork.

    This completes the file capture, not a restore test. Don't overwrite your current
    profile to test it. Contact your administrator or OpenWork support before
    attempting recovery.

    </Step>
    </Steps>

## Custom storage and other installations

Ask your administrator or OpenWork support to confirm the desktop profile, runtime
folder, and history database paths before copying. Relevant overrides include
`OPENWORK_ELECTRON_USERDATA`, `OPENWORK_SERVER_CONFIG`, `OPENWORK_RUNTIME_DB`,
`OPENCODE_DB`, `XDG_CONFIG_HOME`, and `XDG_DATA_HOME`. A saved engine selection may
point at another history database. Share only paths. Don't share configuration
files or credentials.

A populated `~/Library/Application Support/opencode` on macOS or
`%APPDATA%\opencode` on Windows may be another OpenCode data store. Keep it in a
distinct backup location until your administrator confirms its role. A local copy
can't capture history held by an external or remote engine.

## What this backup includes

The folder set includes the desktop profile, OpenWork runtime state, and original
OpenCode data. History may be in the original data folder or a separate engine
store inside the runtime folder. Save the complete set, not whichever database
filename looks newest.

Whole-folder capture includes SQLite's write-ahead log, whose name has a `-wal`
suffix. A live copy of the database and its sidecars doesn't establish a consistent
capture. This is why you quit the apps first and copy folders rather than a single
`.db` file.

This isn't a complete backup of workspace documents, global skills, or OS-protected
credentials. You don't need to copy every project folder just to save the standard
chat stores. If a conversation links to an original local file outside these
folders, save that file in its own backup location if you need its original bytes.

File copies don't export the OS keychain or keyring or make sign-in credentials
portable between computers, users, or operating systems.
