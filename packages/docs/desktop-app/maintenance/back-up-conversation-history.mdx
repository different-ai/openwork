---

OpenWork keeps local conversation history and the app state that points to it in
several folders. To make a file backup, fully quit the apps that use those stores,
then copy the complete folder set for your operating system.

This guide covers standard **local desktop installations**. It does not back up
OpenWork Cloud, a remote engine, or your organization's server database.

## Before copying

1. Finish running tasks and fully quit OpenWork. On macOS, use **OpenWork → Quit**
   or **Command-Q**, not just the window's close button. Close other OpenWork or
   OpenCode instances using the same data. If an app does not close normally,
   ask IT or support for help before copying.
2. Create a dated backup folder outside the folders you are saving. Use an
   encrypted or IT-approved protected location. Record the app version and each
   source folder's original path.
3. Copy **every folder listed for your OS**, including hidden files and any
   database sidecar files present. Do not copy only a `.db` file: recent writes
   may still be in its write-ahead log (`-wal`). Copying a live database and its
   sidecars separately does not make a consistent backup.
4. Wait for all copies to finish and resolve any copy errors before reopening
   OpenWork. Leave the original folders unchanged.

<Note>
  The folder set includes the desktop profile, OpenWork runtime state and original
  OpenCode data. History may be in the original data folder or a separate engine
  store inside the runtime folder. Save the complete set, not whichever database
  filename looks newest. If an expected folder is missing, confirm the active
  storage paths rather than creating an empty replacement.
</Note>

## Windows

Paste each path into the **File Explorer address bar**, then copy the whole
folder. These are navigation paths, not PowerShell commands.

```text
%APPDATA%\com.differentai.openwork
%APPDATA%\openwork
%USERPROFILE%\.local\share\opencode
```

- The first folder keeps the desktop profile and workspace/history navigation state.
- The second keeps runtime state and any separate engine history or recovery material.
- The third keeps the default original OpenCode data, which can also hold current history.

## macOS

In Finder, choose **Go → Go to Folder** or press **Shift-Command-G**. Open each
path and copy its entire folder.

```text
~/Library/Application Support/com.differentai.openwork
~/.config/openwork
~/.local/share/opencode
```

These are the desktop profile, OpenWork runtime and original OpenCode data folders,
respectively.

## Linux

Open your home folder in the file manager and enable **Show Hidden Files**
(often **Ctrl-H**). Copy each whole folder.

```text
~/.config/com.differentai.openwork
~/.config/openwork
~/.local/share/opencode
```

These are the desktop profile, OpenWork runtime and original OpenCode data folders,
respectively. If `XDG_CONFIG_HOME` or `XDG_DATA_HOME` is set, use the configured
locations instead of assuming these defaults.

## Custom storage and other installations

The default list is not enough if storage has been redirected. Confirm the resolved
paths with IT if your setup uses overrides such as `OPENWORK_ELECTRON_USERDATA`,
`OPENWORK_SERVER_CONFIG`, `OPENWORK_RUNTIME_DB`, `OPENCODE_DB`, `XDG_CONFIG_HOME`
or `XDG_DATA_HOME`. A saved engine selection may point at another history database.
Use paths only for this check; do not share configuration contents or credentials.

A populated `~/Library/Application Support/opencode` on macOS or
`%APPDATA%\opencode` on Windows may be another OpenCode data store. Keep it
separately until its role is confirmed. A local copy cannot capture history held
by an external or remote engine.

## What this backup includes

This folder capture is for **conversation records and the app/runtime state needed
to find them**. It is not a complete backup of workspace documents, global skills
or OS-protected credentials. You do not need to copy every project folder just to
save the standard chat stores. If a conversation links to an original local file
outside these folders, save that file separately if you need its original bytes.

The copied folders can contain chats and credentials. Keep the backup private;
do not upload it to a public issue, support chat or Slack. File copies do not export
the OS keychain/keyring or make sign-in credentials portable between computers,
users or operating systems.

Before relying on a backup for recovery, have IT validate it in a separate test
environment. A completed folder copy alone is not proof of a successful restore.
