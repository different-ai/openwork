OpenWork keeps local conversation history and the app state that points to it in
several folders. This guide shows you how to copy that folder set after you quit
the apps that use it.

This guide covers standard **local desktop installations**. It doesn't back up
OpenWork Cloud, a remote engine, or your organization's server database.

## Before you begin

Use the tables for your operating system to locate the source folders before you
start copying. If your installation uses custom storage, any listed folder is
missing, or you aren't sure which folders hold your history, stop before copying.
Ask your administrator or OpenWork support to confirm the desktop profile, runtime folder,
and history database paths. Share paths only, not configuration files or
credentials. See [Custom storage and other installations](#custom-storage-and-other-installations).

The folder set includes the desktop profile, OpenWork runtime state, and original
OpenCode data. History may be in the original data folder or a separate engine
store inside the runtime folder. Save the complete set, not whichever database
filename looks newest.

## Prepare the backup

1. Finish running tasks and fully quit OpenWork. On macOS, use **Quit** from the
   app menu, not just the window's close button. Close other OpenWork or
   OpenCode instances using the same data. If an app doesn't close normally, ask
   your administrator or support for help before copying.
2. Create a dated backup folder outside the folders you are saving. These folders
   can contain private conversations and credentials. Store the backup in an
   encrypted or IT-approved protected location. Don't upload it to a public issue,
   support chat, or Slack.
3. Record the app version and each source folder's full original path. If two
   source folders have the same name, create distinct destination folders and
   record which source belongs in each. Don't merge or replace copies from
   different sources.

Copy the **named source folder itself**, not just its visible contents. This
includes hidden files and any database sidecar files present. Don't copy only a
`.db` file: recent writes may still be in its write-ahead log. That file has a
`-wal` suffix. A live copy of the database and its sidecars doesn't establish a
consistent capture.

## Windows

Use these parent folders and source names in File Explorer. These are navigation
paths, not PowerShell commands.

| Open this parent folder | Select this folder |
| --- | --- |
| `%APPDATA%` | `com.differentai.openwork` |
| `%APPDATA%` | `openwork` |
| `%USERPROFILE%\.local\share` | `opencode` |

1. In the **File Explorer address bar**, enter the parent path for one row and
   press **Enter**.
2. Select the named source folder itself, then use **Copy**, not **Cut**.
3. Open the dated backup destination and use **Paste**. Repeat for every source
   folder, keeping each copy paired with its original path.

## macOS

Use these parent folders and source names in Finder.

| Open this parent folder | Select this folder |
| --- | --- |
| `~/Library/Application Support` | `com.differentai.openwork` |
| `~/.config` | `openwork` |
| `~/.local/share` | `opencode` |

1. In Finder, choose **Go** > **Go to Folder**. Enter the parent path for one row
   and press **Return**.
2. Select the named source folder itself, then choose **Edit** > **Copy**.
3. Open the dated backup destination and choose **Edit** > **Paste Item**. Repeat
   for every source folder, keeping each copy paired with its original path.

## Linux

In these paths, `~` means your home folder. Show hidden files in your file manager
if needed to find `.config` or `.local`.

| Open this parent folder | Select this folder |
| --- | --- |
| `~/.config` | `com.differentai.openwork` |
| `~/.config` | `openwork` |
| `~/.local/share` | `opencode` |

1. In the file manager, open the parent folder for one row.
2. Select the named source folder itself and use **Copy**. Don't use **Cut** or **Move**.
3. Open the dated backup destination and use **Paste**. Repeat for every source
   folder, keeping each copy paired with its original path.

If you set `XDG_CONFIG_HOME` or `XDG_DATA_HOME`, use the configured locations
instead of assuming these defaults.

## Check the file capture

Wait for all transfers to finish. The file capture is complete when every required
folder has copied without errors and you have recorded each original path. If a
copy fails or a required folder is missing, resolve the issue before treating the
capture as complete. Leave the originals unchanged. Reopen OpenWork only after
all copying has finished.

Recovery remains unverified until tested in a separate environment. Contact your
administrator or OpenWork support before attempting recovery. Don't overwrite
your current profile to test the backup.

## Custom storage and other installations

If you redirected storage, confirm the resolved paths with your administrator
before copying. Relevant overrides include `OPENWORK_ELECTRON_USERDATA`,
`OPENWORK_SERVER_CONFIG`, `OPENWORK_RUNTIME_DB`, `OPENCODE_DB`, `XDG_CONFIG_HOME`,
and `XDG_DATA_HOME`. A saved engine selection may point at another history
database.

A populated `~/Library/Application Support/opencode` on macOS or
`%APPDATA%\opencode` on Windows may be another OpenCode data store. Keep it in a
distinct backup location until your administrator confirms its role. A local copy
can't capture history held by an external or remote engine.

## What this backup includes

This folder capture is for **conversation records and the app/runtime state needed
to find them**. It isn't a complete backup of workspace documents, global skills,
or OS-protected credentials. You don't need to copy every project folder just to
save the standard chat stores. If a conversation links to an original local file
outside these folders, save that file in its own backup location if you need its
original bytes.

File copies don't export the OS keychain or keyring or make sign-in credentials
portable between computers, users, or operating systems.
