Agents are in private alpha. OpenWork does not officially support this feature yet, and how it works may change. To try it, ask your OpenWork contact to turn it on for your organization.
</Warning>

These settings apply only to agents. New agents start with connections off unless you choose them at setup. When a connection is on, read-only tools are allowed by default and tools that make changes ask first. Organization tool rules still apply. Built-in connections don't have these settings.

| Setting | What happens |
| --- | --- |
| **Allow** | The agent can use the tool without asking, unless an admin rule says otherwise. |
| **Ask** | The agent needs a yes before it can use the tool. |
| **Block** | The agent can't use the tool. |

## Answer a tool request

When a tool needs a yes, the run doesn't use it. A card in the chat names the tool and connection. An agent knows about the tools on connections that are off, so when your request needs one it asks for that single tool and the rest of the connection stays off. Your skills work the same way: reading them is one tool of the OpenWork connection, called **Read your skills**. The options depend on your role and your organization's rules:

![A request in the chat to let Bug watcher use Create issue in Linear, with Deny, Always allow and Allow once](/images/agents/tool-request.png)

- **Deny** refuses the request.
- **Allow once** covers the tool for the whole of the requester's next run of this agent that calls it. The run that asked can't use it, even if it is still going. A run that doesn't call the tool leaves the approval for the next one. An unused approval expires after 7 days. A block still wins.
- **Always allow** lets the agent use the tool on future runs. A lasting change to tool access needs the owner's approval. This option isn't offered when the organization requires approval for each run.

Approval doesn't resume the run that asked. The app requests another run if you approve your own request. If someone else approves it, you can run the agent again yourself.

## Change a setting

Click the agent's name to open its panel. Go to **Settings**, then **What it can use**. Use the switch next to a connection to turn it on or off for this agent. When it's **Off**, the agent can't use any of its tools. Turn it back on to find the same per-tool choices, and expand the connection to choose **Allow**, **Ask**, or **Block** for each tool.

A manager's change waits for the owner's approval. These settings are separate from the brief. A saved change applies the next time the agent tries to use a tool, even in a run that's already going. Turning a connection on doesn't override [organization tool rules](/agents/tool-permissions).

If your organization has cloud computers turned on, **Computer** appears with the connections. It gives the agent a Linux computer of its own in its chat (routines don't use it yet), for work that needs real programs, files or code. It starts off, and the agent asks in chat when it needs it. The computer has none of your files or sign-ins. Once it's on, the agent runs commands there without asking each time. An admin can turn it off for every agent under **Agents** in the dashboard.

![Settings for Bug watcher: each Linear tool set to Allow, Ask or Block](/images/agents/what-it-can-use.png)

During setup, you can say what the agent should never do. For example, if you say "Never post in Slack," OpenWork tries to block the matching tools. Check **What it can use** to confirm what was blocked.

- **Blocked by your admin** means the setting is locked.
- **Your admin requires this to ask first.** means you can't choose **Allow**. You can still choose **Block**.
- **Allowed by your admin.** doesn't override your **Ask** or **Block**.

## Check spending

In **Settings**, check this month's cost under **Spend**. The owner can set a **Monthly budget**. If several limits apply, the lowest one wins. See [Limits](/agents/limits).
