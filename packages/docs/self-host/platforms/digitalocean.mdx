DigitalOcean offers several deployment shapes for OpenWork: Linux Droplets, a Kubernetes cluster, or container services on App Platform. This is planning guidance; the repository does not ship a tested DigitalOcean-specific installer.

## Deployment approach

For a Droplet, start with [Docker and VM planning](/self-host/platforms/docker-and-vms). For Kubernetes, adapt the published Helm chart to your ingress and database. App Platform's [container image deployment](https://docs.digitalocean.com/products/app-platform/how-to/deploy-from-container-images/) can be assessed for Den web and Den API with Managed MySQL.

## What you need

- Separate web/API services, HTTPS hostnames, and secrets.
- A MySQL 8-compatible database with private connectivity, verified TLS, backups, and a restore plan. App Platform's PostgreSQL development database is not a substitute.
- Migrations completed before API traffic and health checks for both services.
- A worker provisioner and durable workspace/data storage if you enable cloud workspaces.

App Platform's [local filesystem is ephemeral and it does not support persistent volumes](https://docs.digitalocean.com/products/app-platform/how-to/store-data/). Use a separate runtime with appropriate durable filesystem storage for workers; object storage alone does not replace a worker's workspace filesystem.
