OpenWork's published container images can be the starting point for a deployment on a Linux server, VPS, or virtual machine. This includes EC2, Azure VMs, Compute Engine, Hetzner, and Linux guests on Proxmox or VMware.

## Deployment approach

Start with the [Docker Compose evaluation guide](/self-host/evaluate-with-docker-compose). It downloads pinned images and runs the control plane on one machine. For production, adapt the services to your own container setup; the evaluation Compose file is not a production configuration.

## What you need

- A Linux host and container runtime compatible with the selected images, with enough CPU, memory, and disk for your workload.
- Den web and Den API as separate services, plus a MySQL 8-compatible database with durable storage and tested backups.
- A reverse proxy with trusted HTTPS web/API hostnames, private database networking, and secrets outside your repository.
- A migration task before API traffic, health checks, and a restore and upgrade procedure.

Keep evaluation ports on loopback; use the guide's SSH tunnel to evaluate a remote VM. If you need cloud workspaces, plan the worker provisioner and durable runtime storage separately from the control plane.
