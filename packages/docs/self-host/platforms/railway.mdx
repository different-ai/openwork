Railway can run services from container images and provides a MySQL deployment option. You can use those primitives to plan an OpenWork control plane without Kubernetes. This is planning guidance; OpenWork does not provide a tested Railway template.

## Deployment approach

Map Den web, Den API, and the database to separate services. Railway's [Compose translation guide](https://docs.railway.com/guides/docker-compose) describes the platform mapping; use OpenWork's [common requirements](/self-host/platforms/overview#common-requirements) for the service configuration. The evaluation Compose file's development settings should not become production defaults.

## What you need

- Pinned images, service target ports, HTTPS web/API domains, and secrets.
- A [MySQL-compatible database](https://docs.railway.com/databases/mysql) with private connectivity, durable data, verified TLS in production, and a restore plan.
- A migration task completed before exposing the API.
- Health checks and a service lifecycle that keeps required background tasks running.
- Separate worker provisioning and persistent workspace/data storage for cloud workspaces.

Review volume and replica behavior before scaling stateful services. Choosing a container service does not configure an OpenWork worker provisioner.
