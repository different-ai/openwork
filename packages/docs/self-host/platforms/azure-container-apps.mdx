Azure Container Apps provides a container hosting option for adapting OpenWork's team control plane without operating AKS. This page is planning guidance; OpenWork does not ship a tested Container Apps installation template.

## Deployment approach

Plan separate container apps for Den web and Den API, with Azure Database for MySQL or another MySQL 8-compatible database. Translate the [common requirements](/self-host/platforms/overview#common-requirements) into your Container Apps environment. For the tested Kubernetes route, use [Deploy on Azure](/self-host/deploy-to-your-cloud/azure).

## What you need

- Access to compatible images, secrets, and private database networking.
- HTTPS web/API hostnames and ingress target ports matching the services.
- A controlled migration job before the new API receives traffic.
- A scaling policy that keeps required background work running; review scale-to-zero behavior.
- Separate provisioned worker runtimes and durable storage if you enable cloud workspaces.

[Container Apps HTTP ingress](https://learn.microsoft.com/en-us/azure/container-apps/ingress-overview) supports WebSockets but documents a 240-second request timeout. Check the enabled MCP and streaming flows against that limit before committing to the topology.
