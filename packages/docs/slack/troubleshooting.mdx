| Symptom | Check |
| --- | --- |
| The desktop app's **Set up Slack** screen still says "Not set up for your organization" after setup in OpenWork Cloud | Go back to **Library**. Slack shows there once setup is done. |
| **Add Slack** shows only client ID and secret fields, no checklist | Guided setup isn't turned on for your OpenWork (for example, self-hosted). Use the [manual Slack steps](/cloud/share-with-your-team/shared-mcp-connections#slack). |
| Connecting your account fails with “The MCP server refused to start a session (HTTP 400)” | Check that **Agents › MCP** is enabled in the same Slack app whose client ID is saved in OpenWork. This is separate from enabling the assistant bot. See [Slack MCP connection troubleshooting](/cloud/share-with-your-team/shared-mcp-connections#connection-failed-http-400). |
| Setup is unavailable | Private-alpha capability, runtime access, and Individual accounts mode. See [step 1](/slack/set-up-the-slack-app#1-check-alpha-access-and-the-existing-connector). |
| Bot missing from mention autocomplete | Bot installation completed and the bot is invited into that channel with `/invite @openwork`. |
| Slack events URL unverified | Public HTTPS URL, correct connector ID, saved signing secret, and Slack's **Retry** then **Save Changes**. |
| `/openwork` gives a connect link | Complete your own Slack OAuth flow. Connections made before the assistant was installed link automatically on your first message; reconnect only if it still asks. See [Connect your account](/slack/connect-your-account). |
| Bot starts but never finishes | Check failed/active counts and runtime availability; do not treat an acknowledgement as success. |
| DMs work but channel mentions do not | Channel allowlist, channel invitation, connector grants, and assistant enablement. |

To pause the rollout, turn off **Enable @openwork in Slack** in the connector. Disabling new requests cannot recall external actions that have already run.
