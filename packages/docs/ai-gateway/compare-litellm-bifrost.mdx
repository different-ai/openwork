LiteLLM and Bifrost are mature, standalone LLM gateways: you put them in front of model providers and point applications at one OpenAI-compatible API. OpenWork AI Gateway is part of a workspace product: it sits alongside the OpenWork agent app, skill and MCP sharing, and the organization control plane. You do not have to choose, because OpenWork can use a LiteLLM or Bifrost gateway you already run.

## When to use which

- **Choose LiteLLM or Bifrost** when you need a general-purpose gateway for many applications and services, with features such as caching, advanced routing, or guardrails. Neither is tied to an end-user app.
- **Choose OpenWork AI Gateway** when the people using the models are your staff working in OpenWork, and you want model access, skills, MCP connections, and spend in one admin dashboard.
- **Use both** when you already standardize on LiteLLM or Bifrost: keep it as the routing layer and let OpenWork consume it.

## Use OpenWork with LiteLLM or Bifrost

OpenWork works with any OpenAI-compatible endpoint, so an existing gateway plugs straight in:

1. Get the gateway's base URL (usually ending in `/v1`), the model names it exposes, and a key.
2. For one person, add it as a custom provider in the workspace `opencode.jsonc`. See [Add a custom LLM or AI gateway](/start-here/connect-your-stack/add-a-custom-llm).
3. For a team, an OpenWork Cloud admin adds it once as a [custom LLM provider](/cloud/share-with-your-team/custom-llm-provider) with the base URL and model IDs, then grants access to people or teams. Members get it in `Settings > Cloud Providers`.
4. If the gateway issues one virtual key per person (for example, LiteLLM virtual keys), use [per-member LLM credentials](/cloud/share-with-your-team/per-member-llm-credentials) so each member gets their own key.

Your gateway keeps doing routing, budgets, and logging. OpenWork adds the agent app, shared skills, and MCP connections on top.

## FAQ

<AccordionGroup>
  <Accordion title="Is OpenWork AI Gateway a replacement for LiteLLM?">
    Not in general. LiteLLM is a standalone gateway for any application. OpenWork AI Gateway manages model access for people using OpenWork. Many teams can use both.
  </Accordion>
  <Accordion title="Can OpenWork use my existing LiteLLM proxy?">
    Yes. Add it as an OpenAI-compatible custom provider, and use per-member credentials if each person has their own virtual key.
  </Accordion>
  <Accordion title="Can OpenWork use Bifrost?">
    Yes, through Bifrost's OpenAI-compatible API, the same way as any custom provider.
  </Accordion>
  <Accordion title="Do all three have an MCP gateway?">
    Yes. LiteLLM and Bifrost include MCP gateway features. OpenWork's MCP Gateway is a separate endpoint that also delivers your organization's skills, plugins, and connections to external agents.
  </Accordion>
  <Accordion title="Which one can I self-host?">
    All three. OpenWork self-hosts with Helm; see [Self-host](/start-here/self-host).
  </Accordion>
</AccordionGroup>
